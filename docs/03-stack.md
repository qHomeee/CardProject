# Обоснование стека приложения Запомни

Практика 3 · Версия 0.1 · 4 ноября 2026 года

## 1 Решение и существующая основа

Для MVP выбираем Kotlin и Jetpack Compose, Clean Architecture с отдельным domain, MVVM, Koin с обычным DSL, Ktor Client, Room и Preferences DataStore. Сервер — обязательный по заданию FastAPI, SQLAlchemy, Alembic и PostgreSQL. Выбор связан с ТЗ: семь экранов, локальное обучение, каталог с сервера и подменяемое управление жестами.

Существующий проект KotlinProject сохраняется. На этом шаге зависимости и исходники приложения не менялись; новые библиотеки подключаются в соответствующих практиках после проверки конкретных версий. Таблица ниже фиксирует фактическую основу, а не заявляет совместимость всего будущего MVP.

## 2 Инструменты Android

| Задача | Выбранный инструмент | Обоснование и границы |
| --- | --- | --- |
| Интерфейс и темы | Compose и Material 3 | Уже используются шаблоном; один набор компонентов для светлой и тёмной тем, адаптивной компоновки и UI-тестов |
| Асинхронная работа | Coroutines и Flow | suspend для операций, Flow для наблюдения, StateFlow для UiState. Источники и диспетчеры подменяются в тестах [21] |
| Внедрение зависимостей | Koin Classic DSL | Явные связи через single { ... }, factory { ... }, ViewModel DSL. Для небольшого графа не нужен compiler plugin; ошибки графа проверяем тестами [6] |
| Сеть | Ktor Client с OkHttp engine | suspend-запросы, общие настройки ошибок и таймаутов; движок поддерживает Android 5.0+, что ниже minSdk 24. DTO остаются в data [7] |
| JSON | kotlinx.serialization | Явные DTO; compiler plugin согласуется с фактической версией Kotlin. JSON-модели не передаются в UI и domain [26] |
| Локальная БД | Room 2.8.x и KSP | Кандидат 2.8.5 из официальной ветки Room 2; minSdk 23 совместим с 24. Транзакции для скачивания и оценки, экспорт схем и миграционные тесты [9] |
| Настройки | Preferences DataStore | Небольшие значения темы, жестов и времени напоминаний; асинхронное чтение через Flow. Карточки и историю храним в Room [10] |
| Навигация | Navigation Compose | Семь маршрутов и передача ID набора или занятия. Отдельный ViewModel для каждого самостоятельного экрана, типизированные маршруты при подключении [27] |
| Напоминания | AlarmManager и NotificationManager | Неточный локальный будильник, уведомление при наличии карточек к повторению. Точная доставка по минутам не требуется; ограничения заданы в ТЗ |
| Жесты | Android Sensor API за интерфейсом domain | Android-типы изолированы в data. На этапе датчиков выбираем доступный источник ориентации, пороги и нейтральную позицию; предусмотрен фейк |

**Почему Koin.** Hilt допустим по заданию, но для семи экранов выбираем обычные определения Koin без аннотаций и генерации DI-кода. Конструкторы доменных классов остаются обычными Kotlin-конструкторами. Это решение проекта, а не утверждение, что Koin всегда лучше Hilt. KSP понадобится отдельно для Room; отказ от генерации DI не устраняет эту зависимость.

**Версии при подключении.** Кандидат Room ещё не добавлен и не собран с проектом. Ktor, Koin, Serialization, DataStore, Navigation, KSP и инструменты качества получают точные версии в libs.versions.toml после проверки release notes, Kotlin metadata, minSdk, AGP/Gradle и транзитивных зависимостей. Не используем динамические версии или принудительное подавление проверки metadata. Room 2 и Room 3 не смешиваем.

**Время.** Для чистого domain выбираем java.time.Instant и подменяемый Clock-интерфейс. При minSdk 24 понадобится core library desugaring для Android-потребителя; его версию и конфигурацию проверим перед использованием [28]. Domain не зависит от Android, Room, Koin и сетевой библиотеки.

## 3 Сравнение вариантов серверной части

FastAPI зафиксирован в обязательных требованиях. Django с Django REST framework рассматривается как реальный альтернативный вариант для объяснения преимуществ и стоимости решения. Оценка сложности ниже относится к этому учебному проекту; нагрузочные измерения не проводились.

| Критерий | FastAPI | Django и DRF |
| --- | --- | --- |
| API и модели запросов | Python-типы и Pydantic, встроенное формирование OpenAPI [11] | Serializer, ViewSet, Router и ORM-интеграция DRF [12] |
| Валидация | Модели Pydantic и собственные правила предметной области | Serializers и валидаторы DRF |
| Документация API | OpenAPI и интерактивная документация входят в основу | Встроенная генерация схем объявлена устаревшей; для нового проекта предлагается drf-spectacular [14] |
| База и миграции | Выбираем SQLAlchemy и Alembic отдельно | Django предоставляет ORM; DRF работает поверх него |
| Редакторский интерфейс | В MVP достаточно защищённого API и Bruno | Django admin может сократить работу над административным интерфейсом [13] |
| Контроль доступа | Security dependencies; явная проверка ключа редактора [18] | Классы аутентификации и разрешений DRF [12] |
| Тестирование API | pytest и TestClient без внешнего HTTP-сервера [20] | Собственные средства тестирования DRF [12] |
| Соответствие нашему объёму | Один каталог, CRUD и явный контракт без пользовательской регистрации | Полезен при развитии административной системы; для текущего API добавляет настройки Django |

**Выбор FastAPI.** Он соответствует обязательному условию и позволяет выразить небольшой JSON API через типизированные схемы. OpenAPI с примерами, валидация, единый формат ошибок и защищённые изменения будут реализованы и протестированы в практиках 8–11. Наличие средств во фреймворке само по себе эти требования не выполняет.

**Серверный стек.** Целевая среда — Python 3.13; FastAPI, Pydantic, SQLAlchemy текущей стабильной ветки 2.x, Alembic, PostgreSQL и синхронный драйвер Psycopg. SQLAlchemy изолирует доступ к БД [15], Alembic ведёт миграции [16], PostgreSQL хранит каталог и связи наборов с карточками [17]. Точные patch-версии и Python-совместимость фиксируются при создании backend, до первой установки зависимостей.

**Простая модель выполнения.** Для MVP выбираем синхронный SQLAlchemy с отдельной Session на запрос. Маршруты с блокирующим доступом к БД определяем обычным def; не выполняем такой доступ прямо внутри async def. Это соответствует модели выполнения FastAPI [19] и позволяет не вводить асинхронный ORM без необходимости.

## 4 Тестирование и воспроизводимость

**Unit-тесты Android.** Сохраняем JUnit; подключаем kotlinx-coroutines-test для виртуального времени и диспетчеров, Turbine для последовательностей Flow, фейки репозиториев, времени и жестов. Фейк предпочтителен для небольшого интерфейса; MockK добавляется только при появлении задачи, которую он заметно упрощает. Ktor MockEngine проверяет ответы, таймауты и ошибки без реальной сети [8, 21–22].

**UI и покрытие.** Compose UI Test проверяет успех и применимые ошибки каждого экрана. Для domain выбираем Kover с порогом 80%, для presentation-логики — 60%; области расчёта и допустимые исключения будут заданы явно. Kover измеряет JVM-тесты и не заменяет проверку UI на устройстве [23]. Реальное качество жестов подтверждается отдельным сценарием на Android-телефоне.

**Проверки качества.** Выбираем ktlint стабильной ветки, согласованной с синтаксисом проекта [24]. При необходимости запускаем CLI через Gradle-задачу, чтобы не добавлять несовместимый сторонний Gradle-плагин. Android Lint дополняет его проверками Android-ресурсов и платформенных API. KDoc и строки в strings.xml проверяются отдельно в код-ревью.

**Тесты сервера.** pytest, TestClient и подмена зависимостей FastAPI. Не менее десяти unit-тестов проверяют правила, валидацию и ошибки; проверки HTTP-контракта считаются отдельно от unit-тестов [20]. Интеграционные проверки БД выполняются в изолированной тестовой PostgreSQL, без обращения к рабочему серверу. Подмена PostgreSQL на SQLite не считается подтверждением поведения PostgreSQL.

**Фиксация зависимостей.** Android использует Wrapper с контрольной суммой и version catalog без диапазонов. Сервер получит pyproject.toml и файл зафиксированных зависимостей с выбранным менеджером при создании backend. После каждого добавления выполняются сборка, применимые тесты и линтер; совместимость объявляется подтверждённой только для реально проверенной конфигурации.

## 5 Доступ редактора и развёртывание

**Авторизация.** Для единственного типа редакторского доступа выбираем APIKeyHeader X-Editor-Key и секрет EDITOR_API_KEY на сервере [18]. Дополнительно реализуется проверка значения ключа: сама декларация security scheme не проверяет его правильность. Чтение публичное; CRUD общего каталога требует действительного ключа. Ключ хранится в окружении сервера и приватном окружении редактора Bruno, не в APK и не в Git. Ошибки и логи не раскрывают ключ; соединение использует HTTPS.

**Деплой.** Планируем контейнер приложения с Uvicorn и отдельную PostgreSQL с постоянным хранилищем [25]. Миграции запускаются управляемо перед обновлением; секреты передаются окружением. Провайдер, тариф, адрес и резервное копирование выбираются перед практикой 10. Интернет-деплой пока не выполнен и платные ресурсы не создавались.

**Напоминания и датчики.** Разрешения добавляются только для фактически выбранных API. Отказ в уведомлениях и отсутствие датчика оставляют обучение доступным через кнопки. Результаты занятия не зависят от доступности сервера.

| Риск | Последствие | Действие и момент проверки |
| --- | --- | --- |
| R01 Обновления Kotlin и AGP | Несовместимые compiler plugins или metadata | Сохранять прошедшую сборку основу; Kotlin, Compose compiler и Serialization менять согласованно, проверять KSP и Kover до подключения |
| R02 Разные поколения Room | Ошибочные импорты и зависимости | Использовать одну ветку Room 2; перед установкой перепроверить выбранную patch-версию, KSP и minSdk |
| R03 Граф DI | Ошибка разрешения зависимости при запуске | Явные определения Koin и тест сборки графа; конструкторная подстановка фейков в unit-тестах |
| R04 Случайный жест | Двойная или ошибочная оценка | Нейтральная позиция, защита от повторов, блокировка до ответа; фейковые события и проверка телефона в практиках 20–21 |
| R05 Сбой локальной записи | Потеря оценки или частичный набор | Room-транзакции, идемпотентное сохранение; не продвигать очередь до успешной записи |
| R06 Перезапуск и время | Потеря состояния или ошибочный срок | UiState и сохранение оценок; подменяемое UTC-время, отдельное преобразование для местного напоминания |
| R07 Секрет редактора | Несанкционированное изменение каталога | Ключ только вне APK, HTTPS, исключения Git, проверка запроса без ключа и с неверным ключом |
| R08 Интернет-хостинг | Недоступный каталог или потеря серверной БД | Офлайн-снимки на телефоне; постоянное хранилище и проверка восстановления БД при деплое |
| R09 Трактовка практики 10 | Невыполнение требования интеграции | Получить ответ преподавателя о собственном FastAPI-сервере до реализации практики 10; вопрос не считается решённым |
| R10 Разрастание MVP | Рост числа экранов и тестов | Сохранять семь экранов и Must из ТЗ; дополнительные функции рассматривать отдельно |
