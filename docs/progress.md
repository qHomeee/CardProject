# Прогресс проекта Запомни

Дата: 4 ноября 2026 года.

## Текущая практика и шаг

Практика 1 — карточка идеи. Первый шаг: изучение исходного проекта и фиксация проблемы, аудитории, ценности, сценария, границ MVP и аналогов. Реализация приложения не начата. Переход к практике 2 — после закрытия проверки документа и сообщения пользователя о продолжении.

## Выполнено

- Изучены существующие файлы `KotlinProject/`. В них стартовый Compose-экран и шаблонные тесты, предметной логики нет.
- Проверено наличие AGENTS.md в рабочей папке, Android-проекте и родительских каталогах: инструкции не найдены.
- Пользователь подтвердил согласование темы преподавателем.
- Подготовлен README с карточкой идеи и сравнением трёх реальных аналогов по шести критериям. Приведены официальные источники и ограничения сравнения.
- Зафиксированы внешний источник и сценарий аппаратной функции, офлайн и кнопочное управление.
- Добавлены корневые правила исключения локальных настроек, секретов и результатов сборки.
- Создан локальный Git-репозиторий с `main`, исходный шаблон сохранён отдельным коммитом `chore: import existing Android starter`. Документация ведётся в ветке `docs/practice-01-idea`.
- Создан `docs/01-idea.docx`; файл пока является черновиком до визуальной проверки.

## Принятые решения

- Существующие исходники и зависимости не изменяем в рамках практики 1.
- До отдельного переноса Android-проект остаётся в `KotlinProject/`.
- Собственные материалы и прогресс — локальные; сервер хранит общий каталог.
- Разработка идёт по одной практике. Контрольная точка `v0.1-spec` оформляется после практик 1–3.
- Удобство жестов и эффективность обучения не выдаются за подтверждённые результаты.

## Проверки

- Чтение исходников и конфигурации: выполнено; наличие настроек Compose, Kotlin DSL и version catalog подтверждено по файлам.
- `git status --short --branch` в исходной рабочей папке и в `KotlinProject/`: обе команды показали отсутствие репозитория до инициализации.
- Четыре официальных веб-источника об аналогах открыты и сверены 4 ноября 2026 года.
- После успешного `git init` обычный запуск команд завершался ошибкой инфраструктуры `helper_unknown_error: setup refresh had errors`. Доступные проверки продолжены вне песочницы. Для Git использовано только временное доверие к точному пути через `git -c safe.directory=...`; глобальные настройки не менялись.
- Проверка исключений Git: локальные настройки Android, `.env`, кеши IDE и временный генератор исключены. Поиск типовых присваиваний секретов в отслеживаемых исходниках совпадений не обнаружил; это не полноценный аудит безопасности.
- DOCX повторно открыт через `python-docx`: структура читается, таблица содержит 3 аналога и 6 критериев, внешние гиперссылки присутствуют.
- `render_docx.py docs/01-idea.docx --output_dir .tmp/idea-render --emit_pdf`: завершился ошибкой `LibreOffice soffice.exe was not found on PATH`. PNG не созданы, визуальная проверка не выполнена. Практика 1 пока не закрыта.
- Проверка исходной точки `git diff --cached --check` обнаружила уже существовавшие пробелы в `KotlinProject/settings.gradle.kts` и лишнюю пустую строку в `KotlinProject/gradle/libs.versions.toml`. Шаблон сохранён без изменения этих файлов.
- Сборка Android, unit-тесты и линтер не запускались: на этом шаге изменяется документация. Наличие шаблонных тестов не означает, что они проходят.

1. Преподавателю: засчитывается ли собственный FastAPI-сервер как внешняя интеграция в практике 10? Подтверждения пока нет.
2. Нужен адрес GitHub-репозитория для удалённого подключения и PR, а также GitHub-логин преподавателя для приглашения. Удалённые действия пока не выполнялись.
3. Визуальная проверка DOCX обязательна до сдачи. В комплекте инструментов Windows не обнаружен встроенный LibreOffice; установить доступность рендеринга.

## Следующий шаг

Выполнить рендеринг карточки идеи в среде с доступным LibreOffice, осмотреть все страницы и закрыть практику 1. После сообщения пользователя о продолжении подготовить практику 2 — ТЗ: экраны, требования, user stories, ошибки, офлайн, критерии приёмки, MoSCoW и use-case-диаграмма.

Команда для повторной проверки в среде с установленным LibreOffice, Python и зависимостями рендерера (сам скрипт находится в каталоге навыка documents):

```powershell
python render_docx.py 'X:\vs code\CartProject\docs\01-idea.docx' --output_dir 'X:\vs code\CartProject\.tmp\idea-render' --emit_pdf
```

После этого требуется визуально проверить каждую страницу `page-*.png`; успешная команда сама по себе не завершает проверку оформления.
