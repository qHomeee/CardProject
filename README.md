# Запомни

Учебное Android-приложение для повторения материала по карточкам. Тема согласована с преподавателем.

## Проблема и аудитория

Студентам и школьникам нужно возвращаться к терминам, определениям и иностранным словам. При самостоятельном повторении приходится выбирать материал и отдельно отслеживать сложные вопросы. Это формулировка задачи проекта, а не результат проведённого исследования пользователей.

«Запомни» объединит карточки, историю ответов и расписание повторений. Пользователь сможет заниматься с собственным материалом и заранее скачанными наборами без интернета. Дополнительный способ управления — переворот и наклоны телефона; все действия доступны кнопками.

## Основной сценарий

1. Выбрать набор и начать занятие.
2. Прочитать вопрос и вспомнить ответ.
3. Перевернуть телефон экраном вниз и вернуть обратно либо нажать «Показать ответ».
4. После открытия ответа наклонить телефон вправо («Вспомнил») или влево («Нужно повторить») либо нажать соответствующую кнопку.
5. Сохранить оценку и дату следующего повторения на устройстве.
6. Увидеть результаты занятия.

Ценность — организация повторения и возвращение к сложным карточкам. Увеличение скорости запоминания или успеваемости не заявляется. Удобство жестов ещё предстоит проверить на устройстве.

## Границы первой версии

Планируются каталог с собственного FastAPI-сервера, поиск и просмотр наборов, скачивание для офлайна, полный CRUD собственных наборов и карточек, занятия, жесты с дублированием кнопками, простой тестируемый алгоритм интервального повторения, результаты и локальная статистика, настройки темы, жестов и напоминаний.

Собственные материалы, история повторений и настройки хранятся на устройстве. Обычная регистрация не обязательна. Общий каталог изменяет только авторизованный редактор; административный секрет не попадает в APK.

За границами MVP: чаты, рейтинги, подписки, ИИ-генерация и синхронизация между устройствами. Состав экранов уточняется в ТЗ с учётом макетов, состояний и UI-тестов каждого экрана.

## Внешний источник и аппаратная функция

Источник общего каталога — собственный сервер FastAPI с базой данных. Чтение планируется публичным; изменение — с доступом редактора. При недоступности сервера уже скачанные и собственные наборы остаются доступны, сетевые действия показывают ошибку и кнопку «Повторить».

Аппаратная функция — распознавание последовательности «экраном вниз → возврат» и наклонов после открытия ответа. Планируются нейтральное положение перед следующим действием, защита от повторов, отключение обработки вне активного занятия и кнопки при отсутствии датчика. Выбор датчиков, порогов и фактических разрешений будет обоснован на этапе реализации; сейчас он не утверждён.

## Текущее состояние и файлы

- `KotlinProject/` — существующий стартовый Android-проект с Kotlin, Compose, Gradle Kotlin DSL и version catalog; экран `Hello Android`. Debug-сборка и один шаблонный unit-тест проверены; Android Lint завершён с восемью предупреждениями. Это проверка исходной основы, а не готового MVP.
- `docs/01-idea.docx` — карточка идеи для практики 1; статус проверки указан в `docs/progress.md`.
- `docs/02-tz.docx` — техническое задание для практики 2: семь экранов, 16 функциональных требований, критерии приёмки, шесть user stories, MoSCoW и use-case-диаграмма.
- `docs/03-stack.docx` — практика 3: выбор инструментов, проверка существующих версий, сравнение FastAPI и Django REST framework, тестирование, деплой и риски.
- [Исходник обоснования стека](docs/03-stack.md) и [команды проверки](docs/checks/03-stack.md). `docs/tools/build_stack.py` собирает обязательный DOCX.
- [Исходник ТЗ](docs/02-tz.md) — рабочая версия для редактирования. `docs/tools/build_tz.py` собирает DOCX и исходники диаграммы; Markdown не заменяет обязательный DOCX.
- [Журнал прогресса](docs/progress.md) — выполненное, проверки, решения и открытые вопросы.

Сохраняем существующую папку `KotlinProject/`. Перенос в `android/` выполним отдельным изменением при создании каркаса, когда проверим сборку. `backend/` появится на серверном этапе.

Этап 1 завершён: практики 1–3 оформлены в DOCX, отрендерены и проверены по всем страницам. Контрольная точка — локальный аннотированный тег `v0.1-spec` на коммите завершения спецификации. После сообщения о продолжении следующий шаг — практика 4: архитектура, сущности, интерфейсы, use cases, диаграмма зависимостей и примеры SOLID.

По уточнению пользователя все изменения коммитятся непосредственно в `main`; прежние ветки практик объединены в неё и удалены. Push пользователь выполняет самостоятельно после сообщения о готовности. GitHub remote пока не настроен; приглашение преподавателя ещё не выполнено. Правила дальнейшей работы зафиксированы в `AGENTS.md`.
