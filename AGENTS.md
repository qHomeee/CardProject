# Правила Git для проекта Запомни

Уточнение пользователя от 4 ноября 2026 года заменяет первоначальный порядок с фича-ветками и PR:

- Работать и создавать коммиты непосредственно в `main`.
- Новые ветки создавать только по отдельной просьбе пользователя.
- Использовать Conventional Commits и сохранять существующую историю.
- Создавать небольшие коммиты по ходу работы после каждого самостоятельного законченного изменения: содержание документа, диаграмма, отдельная функция с тестами, исправление после проверки. Размер и частота определяются смыслом изменений; одна практика может содержать несколько коммитов. История должна отражать фактическую последовательность работы.
- Push выполняет пользователь самостоятельно. После завершённого локального изменения сообщать, когда можно пушить; не выполнять push автоматически.
- Контрольные теги создавать после выполнения требований соответствующего этапа. `v0.1-spec` относится к завершению практик 1–3.
